# 02 · PRD：定位、页面、用户任务、内容结构

## 愿景和目标

**一句话**：Made by TMY 是一名独立 Web 开发者的真实作品集，记录已发布工具、小游戏和研发过程，帮助访客直接了解项目、使用产品并找到开发者。

**P0 必须实现**：独立品牌主页、项目总览、项目详情模版、关于作者、可维护内容数据、静态预渲染、基础 SEO、移动端响应式、可访问、可部署。

**P1 可选**：轻量开发日志、项目技术报告、搜索/筛选、主题切换、第二语言、RSS。

**明确不做**：用户账户、评论系统、后台 CMS、付费服务、排名承诺、批量低质量自动生成的项目页/文章、站群互链工具。

## 受众和任务

- 访客：用 10–20 秒明白作者做什么，再点击实际可用项目。
- 开发者 / 潜在合作方：查看技术栈、项目痛点与开发职责，确认联系方式。
- 搜索引擎：无需执行 JS 就能获取标题、描述、正文、自然链接和结构化数据。
- 站点维护者：通过一处结构化数据更新项目卡片及详情页，确保不泄漏草稿地址。

## 信息架构

| URL | 主要内容 | 是否索引 | 发布要求 |
|---|---|---|---|
| `/` | Hero、自我简介、代表作品、项目入口、技能、简短开发理念 | 是 | 首发 |
| `/projects/` | 全部**已发布**项目列表、分类与标签 | 是 | 首发 |
| `/projects/[slug]/` | 单个项目的角色、问题、功能、演示、技术方案、限制、相关链接 | 已发布且内容完整才索引 | 首发 ≥1 个 |
| `/about/` | 真实身份呈现方式、背景、方法、GitHub 等真实账号 | 是 | 首发 |
| `/notes/` | 开发笔记列表 | 内容实际准备好后 | 二期 |
| `/notes/[slug]/` | 原创日志与问题排查 | 写完且有实际价值后 | 二期 |
| `/404` | 明确不存在的路径 | 否 | 首发 |

全部规范 URL 采用末尾 `/`（可根据生成产物改为不带尾斜杠，但**全站必须统一**），实际路由、canonical、sitemap 一致；www 与 http 301 到唯一 HTTPS 主域。

## 首页结构

1. Hero：`TMY · Independent Developer` / `I build small tools that solve real problems.`；简短真实描述，不自称团队/公司。
2. Featured Projects：筛选 `status=published` 且 `featured=true` 的 2–4 个项目，可少于 2 个，绝不补假项目凑数。
3. What I work on：开发者工具、数据处理、轻量 Web 应用；只写真实能力与经历。
4. Building Notes：仅当有实际公开文章时出现。
5. About / Contact：个人资料、真实 GitHub、邮箱（公开前经用户确认）。
6. Footer：导航、版权、政策性说明（如隐私处理情况、外部链接提醒）；不塞关键词链接矩阵。

## 项目卡片最小内容

- `name`、`tagline`、简短真实描述、category、实际访问 URL（仅 published）、发布年份（确有根据才填）、技术标签（确有根据才填）。
- 最多 2 个深层外链，优先对应用户实际任务（如 Large JSON Viewer），并经过 URL 检查。
- 每张卡片对应本站项目详情页，说明开发背景与具体角色；避免全站只剩“跳转门面”。

## 详情页信息

`Overview` → `Problem` → `Solution / Features` → `Technical notes` → `Constraints & trade-offs` → `Open project` → `Related notes`；没有事实材料的章节直接省略，绝不编造使用人数、性能数据或商用收入。

## UI 原则

支持 320px 手机至桌面；简洁信息层级，优先可读性。视觉由 Codex 自主实现，不需固定颜色方案。必须有键盘焦点、清晰 hover/focus、适当对比度、动效节制及 prefers-reduced-motion。外链的新窗口打开要明确提示，并带 `rel="noopener noreferrer"`（nofollow 根据链接性质而非统一添加）。
