# 10 · 上线后 0 / 7 / 14 / 30 天观察计划

> 下列日期是**观察节奏**，并不是保证搜索引擎在指定时间内抓取/编入索引。

## Day 0：技术上线

- 记录生产部署 SHA、Build 输出目录、生产 URL、部署时间。
- 手工检查 200/301/404/robots/sitemap/canonical/HTML 正文/可点击外链。
- Search Console 验证域名资产；Bing Webmaster Tools 验证站点资产（如果支持导入可用官方流程）。
- 提交 Sitemap；对 homepage + 1 详情页各跑 URL Inspection，保存检查结果。
- 记录首次监测基线（通常可能均为 0，属于正常初期状态）。

## Day 7：发现与爬取诊断

- GSC：已发现、已抓取、已索引、重复/重定向/robots/noindex 状态。
- Bing：URL Inspection + Site Explorer（避免拿 site: 估算做精确入库数）。
- 排查爬虫抓取失败：HTTP 状态、页面首包、缓存/WAF/Cloudflare bot 管理、URL 规范化。
- 若没被索引，首先确认内容独特性/页面用途，**不**简单重复点击“请求编入索引”。

## Day 14：内容和链接质量

- 看哪些主页入口/项目详情有真实访问，并核对其对用户是否有价值。
- 核查外链是否跳转到真实功能页，是否有 404 / 重定向链、过期项目说明。
- 如果项目详情仍十分薄弱，补充真实设计权衡、技术挑战、截图或亲自总结，而非机器凑字数。
- 若有自然的作者署名需求，可在 tinystool.org/about/ 添加**一条**个人网站链接；新增前做好版本备份，不为“权重”全站遍历加外链。

## Day 30：形成改进判断

- 对比 GSC 的曝光、点击、已索引页面趋势（注意样本量很小、数据延迟）；Bing 单独分析。
- 核实首页 / 主要项目页是否能被检索和访问，是否存在明显的技术阻断。
- 比较项目页的访问路径与 CTA 表现（如果需要埋点，先由用户决定是否使用隐私友好的分析）。
- 对最有价值的项目补充更完整的原创技术说明；继续维护链接与展示准确性。
- 如预计再增加项目，考虑项目详情可维护性；若没有内容，不必空建博客。
